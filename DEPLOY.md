# Розгортання на VPS

Демо працює тим самим `docker compose`, що й локально. Caddy сам отримує сертифікат Let's Encrypt для вашого домену.

## 1. Що потрібно на VPS

- Docker з плагіном Compose (`docker compose version` має відповідати).
- Вільні й відкриті порти 80 і 443. Якщо працює фаєрвол `ufw`:

```bash
sudo ufw allow 80,443/tcp
```

Порт 80 потрібен, навіть якщо сайт працює лише на HTTPS: через нього Let's Encrypt перевіряє, що домен ваш.

## 2. Домен на DuckDNS

1. Увійдіть на [duckdns.org](https://www.duckdns.org) через GitHub чи Google.
2. Створіть піддомен, наприклад `nova-post`, і вкажіть у полі «current ip» публічну IP-адресу VPS.
3. Перевірте, що домен вказує на сервер (має показати IP вашого VPS):

```bash
dig +short nova-post.duckdns.org
```

У VPS постійна IP-адреса, тож налаштувати це треба один раз, програма для оновлення IP не потрібна.

## 3. Код і налаштування

Скопіюйте репозиторій на VPS зручним вам способом, без папок `node_modules`, `web/dist` і `tmp`. Потім у папці проєкту:

```bash
cp .env.example .env
```

Заповніть `.env`:

- `SITE_ADDRESS` — ваш домен, наприклад `nova-post.duckdns.org`;
- `APP_SECRET` і `INGEST_SECRET` — випадкові рядки;
- `ADMIN_PASSWORD`, `SENIOR_PASSWORD`, `OPERATOR_PASSWORD` — паролі, які ви надішлете людям з НП.

Випадковий рядок можна згенерувати так:

```bash
openssl rand -hex 32
```

Якщо якесь значення лишиться типовим, backend напише в лог `WARNING: default values in use for …`.

## 4. Запуск

```bash
docker compose up -d --build
```

Стежте, як Caddy отримує сертифікат (перший раз це займає до хвилини):

```bash
docker compose logs -f web
```

Шукайте рядок `certificate obtained successfully`. Перевірка:

```bash
curl -s https://nova-post.duckdns.org/api/locations
```

Відкрийте сайт, увійдіть як «Симулятор» і натисніть «Показати кейс».

## 5. Оновлення

Скопіюйте новий код поверх старого (файл `.env` не чіпайте) і виконайте:

```bash
docker compose up -d --build
```

Дані демо в Postgres зберігаються між оновленнями. Якщо емулятор перезапуститься, backend за кілька секунд сам відновить у ньому сценарій, годинник і дії операторів.

## Якщо щось не так

| Симптом | Причина й рішення |
|---|---|
| Caddy пише помилку отримання сертифіката | DuckDNS ще не вказує на VPS (перевірте `dig`) або закритий порт 80 |
| Браузер попереджає про сертифікат | `SITE_ADDRESS` не задано, і Caddy видав локальний сертифікат для `localhost` |
| «Забагато невдалих спроб» на вході | 10 невдалих спроб з однієї IP за 15 хвилин; зачекайте або перезапустіть backend |
| Екрани порожні, «Емулятор недоступний» | `docker compose ps`: усі чотири сервіси мають бути `running` |

## Що закрито ззовні

- Назовні відкриті лише порти 80 і 443 (Caddy). Postgres, backend і емулятор доступні тільки всередині docker-мережі.
- Вебхук емулятора `/api/ingest/*` ззовні віддає 404.
- Адмін-API емулятора назовні недоступне.
- Postgres слухає лише `127.0.0.1:5432`, тобто доступний тільки з самого сервера.
