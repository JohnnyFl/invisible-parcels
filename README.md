# Невидимі посилки

Концепт для Нової пошти. Система звіряє те, що бачить клієнт у трекінгу, з тим, що бачить оператор відділення, і показує посилки, які от-от загубляться: доїхали, але не відскановані; приїхали не туди; невідомі, які повертають навмання.

Проблема, причини й рішення описані в [docs/problem-solution.md](docs/problem-solution.md), технічна специфікація — в [docs/spec.md](docs/spec.md).

## Що всередині

| Сервіс | Що робить |
|---|---|
| `emulator` (Go) | Імітує Нову пошту: віддає статуси у форматі API НП v2.0 і надсилає події сканування вебхуком |
| `backend` (Go, Echo, PostgreSQL) | Зберігає події, рахує проблемні посилки, віддає API й живі оновлення (SSE) |
| `web` (React, Vite, TanStack) | Екрани оператора, старшої зміни, клієнта й симулятора |

## Розробка

Потрібні Go 1.27+, Node 24+ і Docker. Кожну команду запускайте у своєму терміналі:

```bash
make db
```

```bash
make backend
```

```bash
make emulator
```

```bash
make web
```

Відкрийте http://localhost:5173. Backend і емулятор перезапускаються самі при збереженні файлу, фронтенд оновлюється без перезавантаження сторінки.

## Повний запуск у Docker

```bash
make up
```

Відкрийте https://localhost. Caddy видає локальний сертифікат. Щоб браузер не попереджав, один раз довірте його кореневий сертифікат:

```bash
docker compose cp web:/data/caddy/pki/authorities/local/root.crt ./caddy-root.crt
```

і додайте `caddy-root.crt` у системне сховище сертифікатів (на macOS: двічі клікніть і позначте «Завжди довіряти»). Або підкладіть сертифікат з `mkcert`.

## Паролі

| Роль | Пароль за замовчуванням | Змінна |
|---|---|---|
| Оператор (відділення вибирається при вході) | `operator` | `OPERATOR_PASSWORD` |
| Старша зміна | `senior` | `SENIOR_PASSWORD` |
| Симулятор | `admin` | `ADMIN_PASSWORD` |

Поза локальною розробкою задайте також `APP_SECRET` та `INGEST_SECRET`. Клієнтський трекінг (`/track`) працює без входу.

## Як показати демо

Найпростіше: увійдіть як «Симулятор» і натисніть «Показати кейс». П'ять кроків проведуть через історію посилки самі.

Вручну:

1. Увійдіть як «Симулятор» і запустіть сценарій «Скани завантаження й вивантаження пропущено».
2. Перемкніть режим на «Як зараз» і дочекайтеся (або натисніть «+6 год» кілька разів), поки рейс прибуде у Київ. Зліва клієнт бачить «орієнтовно 18.10, 15:00 (прогноз)», справа оператор не бачить посилки навіть у списку надходжень.
3. Перемкніть на «З рішенням»: оператор бачить посилку в надходженнях, а потім помаранчеву позначку «Розірваний ланцюг», яка через 6 годин стає червоною.
4. В іншому браузері (або приватному вікні) увійдіть як оператор «Київ, Відділення №12». У панелі «Склад» відскануйте посилку 59 0000 0000 0001 і натисніть «Прийняти». Проблема зникне, а клієнт побачить «Прибув у відділення».

Інші сценарії і на яке відділення дивитися підписані на екрані симулятора. Кнопка «Додати 5 випадкових посилок» додає до поточного світу посилки з випадковою долею і показує, на чий екран дивитись.
